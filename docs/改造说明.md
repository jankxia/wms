# 改造说明（相对原版 chenbool/wms）

原版：ThinkPHP 5.0.24 单模块 + MySQL，功能停在「能录单」的程度：入库出库都是先写单据、再单独改库存，没有事务；出库不校验库存；删单据库存不回滚；PHP 8 下 PHPExcel 直接语法报错；登录密码是 md5；调试页会把环境变量和 SQL 全打印出来；还绑着扫码枪和条码打印。

下面是这一版做了哪些改动、为什么改。

## 1. 去掉扫码枪 / 条码

| 文件 | 改动 |
|---|---|
| `extend/Barcode.php` | 删除（原用于生成条码图片） |
| `app/controller/Instorage.php`、`app/controller/Outstorage.php` | 删除 `barcode($sn)` 动作 |
| `app/view/pack/send.html` | 条码图片改为「单号：xxx」文本，去掉 avalon 的 `barcode` 变量与 `getBarcode()` 请求 |
| `app/view/pack/prints.html` | 打印页条码图改为单号文本 |

业务上不再有任何环节要求扫枪输入；单据号靠系统生成或手工录入。

## 2. 库存与单据的一致性（核心）

原版的问题：

- `InstorageService::save()` 先 `Order::create()` 再循环改库存，中途失败就半截数据；
- `OutstorageService::save()` 出库数量大于库存也照扣，库存能被扣成负数；
- `delete()` 只删单据不删明细，库存不回滚，账实不符；
- 没有流水，事后查不到「谁在什么时候把库存从 A 改成 B」。

现在：

- 新增 `app/service/StockService.php`：
  - `normalizePairs()`：校验 `product[]`/`num[]`（必填、数字、>0），同一产品多行自动合并；
  - `applyPairs()`：在事务内改库存，减少库存前校验 `现有 >= 本次`，写库存后落一条流水；
  - `record()`：写 `w_stock_log`（类型、产品、单据、变动前后数量、操作人、备注、时间）；
  - `rollbackOrder()`：删单据时按明细反向冲销；
  - `page()`、`warningList()`、`dashboard()`：台账分页、预警列表、看板统计。
- 新增 `app/model/StockLog.php`（类型文案、带符号变动值、时间格式化）。
- `InstorageService` / `OutstorageService` 重写：`save()` 全事务（建单 → 改库存 → 写明细，任一步失败整体回滚）；`delete()` 全事务（冲销库存 → 删明细 → 删单据）；单号留空自动生成 `RK/CK + 日期 + 随机`，重复自动加后缀；`totals()` 供单据详情与打印页显示合计数量/金额。
- 出入库类型改为业务上说得通的枚举：入库「采购入库/销售退货/调拨入库/其他入库」，出库「销售出库/采购退货/调拨出库/报损出库」。
- 产品下拉里直接显示当前库存，填数量时不用再翻产品列表。
- 新增产品不再默认 `num=1`（原版新建产品就凭空多 1 个库存），改为 0，起始库存只能通过入库单产生。
- 删除产品前检查：有库存、或已被单据引用时拒绝删除，提示改「废弃」状态。

## 3. 打印模板

`app/view/instorage/prints.html`、`app/view/outstorage/prints.html` 整页重写为正式单据样式：标题、单据号、类型/制单人/往来单位、日期、车牌、板号/清单号、明细表（规格、仓库/库位）、合计行、备注、三方签字栏，并自动弹出打印；同时补了控制器侧的合计计算。

原版这两个页面只有一个条码占位和几行文本，实际没法当单据用。

## 4. PHP 8 兼容

- `extend/Classes/PHPExcel/**` 19 个文件里 220 处 `$var{0}` 花括号下标（PHP 8 已移除）改为 `$var[0]`。
  - 注意：不能用一刀切正则——`Reader/Excel5.php` 里有 `"$op1$space1$space0[$token['data']]$op2"` 这种双引号插值，第一次全量替换把字符串改坏导致语法错误，最后是「排除 `{` 后紧跟 `$` 的情形 + 逐行判断是否在字符串内」才干净。当前 `php -l` 全量 0 错误，`demo.xls` 实测可正常解析。
- `thinkphp/library/think/Response.php::create()`：控制器返回数组且未指定类型时按 JSON 输出。原版所有写接口都是 `return ['error'=>0,...]`，在 PHP 8 下会抛 `variable type error： array` 直接 500。
- `app/service/SystemService.php`：`SHOW VARIABLES LIKE 'character_set_%'` 改 `'%database'`（同时取到 charset 与 collation）、`storage_engine` 改 `default_storage_engine`（MariaDB 没有前者，原版会让系统信息页整块报异常）。

## 5. 安全

| 项 | 改动 |
|---|---|
| 密码 | md5 → `password_hash(PASSWORD_DEFAULT)`；登录时若库里还是 32 位 md5 且校验通过，自动改写成 hash（`hash_equals` 比较，兼容升级）；`w_user.password` 扩到 varchar(255) |
| CSRF | 新增 `app/service/CsrfService.php`，session 下发 token，写操作校验请求头 `X-CSRF-TOKEN` 或 `_token`；`Base::_initialize()` 统一拦截，失败返回 403 JSON；`base.html` 里 `ajaxSetup` 自动带 header |
| 调试信息 | `app_debug` 走环境变量、默认 false，`app_trace` 关闭；同时清掉了仓库自带 `.env` 里的 `DEBUG = true`（它会盖过 config，导致异常页输出环境变量与 SQL）。再配合 `display_errors=Off`，线上异常只显示「页面错误」 |
| 会话 | Cookie `httponly=true`；登录失败 5 次锁 10 分钟（会话级） |
| 越权 | `Base` 里 `$role` 为空不再报「尝试获取非对象属性」，无权限时 AJAX/POST 返回 JSON、GET 返回提示页；`status != 0` 的账号直接清 session 踢出 |
| 超级管理员 | `UserService::delete()` 禁止删除 `config('super_admin')` 里的账号 |
| 安装入口 | `public/install.php` 无鉴权且会改写配置文件，加环境变量开关 `WMS_ALLOW_INSTALL=1` 才可访问，默认 404；仓库内 `install.lock` 仍然有效 |

## 6. 新增功能

- **运营看板**（`Index/index`）：库存总量、库存金额（`SUM(num*price)`）、今日出入库与近 7 天、预警产品数 4 张卡片；快捷入口；最近 8 张单据（带打印链接）；低库存 TOP 8；底部「系统与运行环境」按需 AJAX 加载。
- **库存台账**（`Stock/index`）：按产品名、单号、变动类型、日期区间筛选，显示变动前后数量与操作人。
- **库存预警**（`Stock/warning`）：产品可设「预警下限」（`w_product.min_num`，0 表示不预警），库存低于下限时在看板、预警页、产品列表里标红。
- 产品列表增加「库存 / 预警下限」列，类别/仓库/库位/单位改为名称显示（兼容历史数据里存的是主键还是名称的两种情况）。

## 7. 数据库迁移

`bin/migrate.php`（幂等，可重复执行，Docker 启动时自动跑）：

1. `w_product` 增加 `min_num INT UNSIGNED NOT NULL DEFAULT 0`；
2. 新建 `w_stock_log`（含 product/order/add_time 索引）；
3. `w_user.password` 扩到 varchar(255)；
4. 新增菜单 id=30「库存台账」、31「库存预警」（挂在「仓库作业」下），并给已含菜单 4 的角色补授权；
5. 可选：`WMS_ADMIN_USER` / `WMS_ADMIN_PASSWORD` 重置或创建管理员。

已在本地 MariaDB 10.11 上连续执行两次验证幂等。

## 8. Docker / 飞牛 NAS

| 文件 | 用途 |
|---|---|
| `Dockerfile` | `php:8.2-apache`，装 `pdo_mysql`/`mysqli`/`gd`/`zip`/`mbstring`/`bcmath`/`opcache`，开 `rewrite`，站点根指向 `public/` |
| `docker/php.ini` | 生产向配置：`display_errors=Off`、`expose_php=Off`、时区、上传大小 |
| `docker/apache-vhost.conf` | vhost + `AcceptPathInfo On`（TP 的 `/controller/action` 路由需要） |
| `docker/entrypoint.sh` | 等数据库 → 空库导入 `wms.sql` → 跑 `bin/migrate.php` → 启动 Apache |
| `docker-compose.yml` | app + mariadb 10.11，命名卷保存数据/运行时/上传，端口 `8812:80` |
| `.github/workflows/docker-build.yml` | push 时构建 amd64+arm64 并推 `ghcr.io`，同时导出 amd64 tar 包做 Artifact |
| `docs/部署到飞牛NAS.md` | 飞牛 NAS 三种安装方式、备份恢复、升级、常见问题 |

> 说明：开发机没有 Docker，也无法在本机安装，所以镜像没有在本地 `docker build` 过；镜像结构、compose 语义、entrypoint 的 `bash -n` 语法、PHP/模板逻辑的运行时行为都在本地用 PHP 8.3 + MariaDB 10.11 验证过，最终镜像请以 NAS/CI 的首次构建结果为准。

## 9. 已知未做

- `Pack / Allot / Goodtop / Position / Shelve / Order(商家订单导入)` 这些半成品模块没有动（原版就没写完，Order 的后端服务里还留着复制粘贴的 Unit 逻辑）；本次只保证它们不因公共层改动而报错。
- 权限改动后菜单缓存（`session('user_menu')`、`session('role_permission')`）不即时刷新，需要重新登录；本次在 `quit()` 里补齐了清理，但没有做「清缓存」按钮。
- 单号自动生成用的是「日期 + 随机数」，并发极高时理论上仍可能撞号（有重复后缀兜底）。
